## Порядок работы

1. По матрице U-10-01 определить конкретный остаток и границы, не переделывать уже совпадающее.
2. Открыть ближайший утверждённый эталон и оба навыка. Для отсутствующей компоновки показать отдельные desktop/mobile и получить решение до кода.
3. Перенести согласованное без потери функций/данных; проверить реальный сценарий на отдельной базе.
4. Записать согласование/локальную готовность/проверки/публикацию отдельно; обновить общий реестр.

## Приёмка

- Загрузка/выбор фото/публикация/ошибки/повтор/удаление проверены по действующему набору функций и после reload.
- Правила фото соблюдены; чужие работы недоступны, публичная галерея не меняется без причины.
- Нет нижней панели/overflow/наложений, круглые аватары, действия от 44 px; целевая браузерная проверка важнее одной сборки.
- Перед изменением сверить утверждённые ссылки из UI-журнала. Missing/conflicting элементы сначала обсуждаются. На изменение UI: frontend/root build и целевой браузерный проход; на данные: save/reload/права на отдельной базе.

## Фактические даты и результат

| Событие | Дата / факт |
| --- | --- |
| Согласование | Для выполненного — в источниках; для остатка отдельное уточнение ещё не записано |
| Начало | Не зафиксировано отдельно |
| Сделано локально | См. границу задачи; новая реализация не зафиксирована |
| Проверено | Не выполнено для этой задачи |
| Опубликовано | Отдельная публикация не зафиксирована / не применима |
| Будущий срок | Не назначен |
| Чат-исполнитель | Не назначен |

При выполнении записать: решение пользователя и точный review → изменённые файлы → проверки/ограничения → локальный результат → версия/дата публикации и откат (если был выпуск).

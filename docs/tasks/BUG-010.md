# BUG-010 — Сбой проверки сессии показывается как гостевой вход

Статус: **Готова к воспроизведению и работе по карточке** (`ready`). Обновлено 2026-10-15T21:12:10+07:00 (Asia/Novosibirsk).

[Список](README.md) · [Матрица U-10-01](../V2_REMAINING_UI_AUDIT.md)

## Граница задачи

В Shell.tsx первоначальный refreshMe().catch(...) заменяет любой отказ /api/me объектом с user:null и profile:null. Недоступность сети/5xx неотличима от подтверждённого гостя: кабинет предлагает войти, повтор проверки в этом состоянии отсутствует. Это не удаляет серверную сессию, но скрывает причину и лишает пользователя восстановления страницы без нового входа. Подтверждено кодом; новый браузерный fault injection ещё не проводился.

## Зависимости и разрешение

[U-10-01](U-10-01.md) завершена. Аудит разрешал регистрацию дефекта, не выполнение всей очереди или публикацию. Разделить pending/подтверждённого гостя/ошибку проверки. Конкретное предложение в матрице: принятый Loading/ErrorState, «Не удалось проверить вход» и «Повторить», молочная область и общий Brand/публичная шапка. Перед добавлением отсутствующего состояния обсудить этот вариант по AGENTS; ready разрешает воспроизведение/review. Настоящий guest-ответ сохраняет прежнее приглашение войти; секреты/стек не выводить.

Восстановить API → нажать повтор → тот же аккаунт/нужный кабинет, без пароля и утраты сессии. Проверить настоящий guest и истёкшую сессию отдельно; нет чужих данных/ролевых переходов.

## Приёмка

- Действующие подтверждение входа/пароль/другие сеансы/уведомления и ошибки сохраняются. Auth и клиентское восстановление повторно не переносятся. Если профессиональной роли недоступен существующий recovery API, оформить конкретный UI-разрыв и согласовать точку входа до кода.
- Ничего не раскрывает код/пароль/чужие данные; «Скоро» остаётся честной недоступной функцией.
- Нет нижней панели/overflow/наложений, круглые аватары, действия от 44 px; целевая браузерная проверка важнее одной сборки.
- Перед изменением сверить утверждённые ссылки из UI-журнала. Missing/conflicting элементы сначала обсуждаются. На изменение UI: frontend/root build и целевой браузерный проход; на данные: save/reload/права на отдельной базе.

## Уточнение по аудиту U-10-01 — 15.10.2026

**Конкретный UI-разрыв подтверждён кодом:** Auth.tsx выдаёт recovery-код при регистрации, но не имеет режима восстановления. ClientRecovery доступен только вошедшему client внутри /me; Access/AccountTools не дают восстановления профессиональным ролям. Поэтому вне сессии восстановление недоступно всем трём типам аккаунта, хотя сервер /auth/recover работает без requireUser.

Сначала подготовить/обсудить desktop/mobile вариант из [предложения в матрице](../V2_REMAINING_UI_AUDIT.md): «Забыли пароль?» в принятой auth-карточке, login/code/new password и существующий экран нового кода, ссылка из профессионального /access. Предложение ещё не утверждено; ready разрешает review, зависимый UI до ответа не добавлять. Отдельно проверить уже существующий авторизованный Access: recent=false/password proof, неверный пароль, недоступные провайдеры, auth_error, изменение пароля, подтверждение завершения других сеансов, ошибки/повтор и reload. Для отсутствующих OAuth только честные состояния «Скоро»/недоступно, без внешних подключений F-02. PushButton — U-10-06; клиентскую форму целиком повторно не переносить.

## Порядок работы

1. Пройти на отдельной базе: новый мастер → профиль/услуга/график/публикация; владелец → салон/команда/услуги/графики.
2. Клиент → каталог/работа/карта → запись → результат → кабинет; мастер/владелец → подтверждение/редактирование/завершение.
3. Проверить reload/права/ошибки/пусто, desktop/mobile/короткий экран/reduced-motion и отсутствие нижней панели.
4. Открытые дефекты оформить отдельными BUG карточками; завершить приёмку только при закрытых блокерах.

## Приёмка

- Есть отчёт с матрицей, реальными сценариями и отклонениями, а не только PASS сборки.
- OS-свайп и реальная push-доставка не объявлены проверенными без физического устройства — F-08.
- Перед изменением сверить утверждённые ссылки из UI-журнала. Missing/conflicting элементы сначала обсуждаются. На изменение UI: frontend/root build и целевой браузерный проход; на данные: save/reload/права на отдельной базе.

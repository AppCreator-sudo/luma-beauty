## Порядок работы

1. Прочитать источники ниже, сопоставить map.png с реальными фильтрами, API видимой области, группами, списком, выбором и ближайшим окном.
2. Составить матрицу desktop/mobile и состояний: загрузка, пусто, ошибка, группа, выбранный мастер/салон, узкий/короткий экран.
3. Подготовить отдельные уточнения только для отсутствующего/противоречивого. Показать desktop/mobile и получить решение пользователя до переноса.
4. Сохранить новый review отдельно и записать ссылку/дату решения в эту карточку и U-09-02.

## Приёмка

- Все действующие действия имеют место в компоновке; неизвестное не решено молча.
- Не меняются Leaflet/OSM/атрибуция/провайдер геокодирования/SQLite. Нет нижней панели.
- Есть согласованные недостающие состояния и mobile; исходный map.png не перезаписан.
- Перед изменением сверить утверждённые ссылки из UI-журнала. Missing/conflicting элементы сначала обсуждаются. На изменение UI: frontend/root build и целевой браузерный проход; на данные: save/reload/права на отдельной базе.

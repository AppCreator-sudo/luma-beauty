# BUG-008 — Мастер: ошибки удаления услуги и работы не показаны

Статус: **Опубликовано** (`published`). Обновлено 2026-10-15T22:26:33+07:00, Asia/Novosibirsk.

[Список](README.md) · [Матрица](../V2_REMAINING_UI_AUDIT.md) · [Отчёт и снимки](../ui-checks/2026-10-15-master-deletion/README.md)

## Граница задачи

До исправления обработчики DELETE услуги и работы в Studio.tsx не перехватывали ошибки. Пользователь не видел объяснения и мог отправить повторное удаление; возникало необработанное отклонение Promise. Обе ошибки воспроизведены браузером на отдельной базе до новой сборки.

Исправлено только удаление в кабинете самостоятельного мастера: сообщение об ошибке и ходе запроса у конкретной строки/работы, повтор после отказа, подтверждение успеха, синхронная блокировка повторного DELETE. Действующая композиция/прайс/галерея и стандартный confirm сохранены.

## Зависимости и разрешение

[U-10-01](U-10-01.md) завершена. Прямое «ок, продолжай» после U-10-02 выбрало следующую BUG-008 из checkpoint. Очевидный дефект принятого UI исправлен без нового концепта. Первоначальная приёмка была локальной; фактический выпуск указан ниже. GitHub push в этом этапе не выполнялся.

## Порядок работы

1. Обе исходные ошибки воспроизведены DELETE500: объект оставался, видимого alert не было, Promise отклонялся без обработки.
2. Общий ref-lock/disabled/pending, target-specific role=alert, понятное сетевое сообщение и retry; успешный DELETE сначала применяется к локальным данным, затем список обновляется.
3. На 1440/390/320 выполнены перечисленные ниже сценарии, обе сборки и визуальная проверка.
4. Карточка/реестр/checkpoint/state/roadmap/UI-журнал обновлены; следующая U-10-03, не автоматическое выполнение всей очереди.

## Приёмка

- Отмена отправляет 0 DELETE. Ответ500/сеть сохраняют объект и дают видимый alert у нужного элемента; кнопка снова доступна.
- Быстрая двойная активация до React render отправляет ровно1 DELETE; пока запрос удерживается, удаление заблокировано.
- Успешный повтор удаляет нужный объект; reload подтверждает результат. Если GET обновления после DELETE200 отказал, удалённый объект не возвращается; «Повторить обновление» не отправляет второй DELETE.
- Реальный409 услуги, связанной с работой, показан без удаления. Визиты (включая визит по удалённой услуге), кабинет/визиты другого мастера и прежние права API сохранены.
- 61/61 browser/API пункт, JS errors0, overflow0, 15 снимков, действия44×44px на 1440/390/320. Frontend/root build PASS; integrity/FK PASS, 172 эталона/manifest неизменны. Полный suite и остальные UI-области этой проверкой не объявлены принятыми.

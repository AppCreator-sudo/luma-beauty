# BUG-012 — Старый PUT профиля допускает публикацию без проверки готовности

Статус: `ready`. Обновлено 2026-10-15T21:47:41+07:00, Asia/Novosibirsk.

[Общий список](README.md) · [U-10-02](U-10-02.md) · [Результаты](../ui-checks/2026-10-15-master-onboarding/README.md)

## Граница задачи

При чтении server.mjs в U-10-02 обнаружен отдельный legacy-путь: PUT /api/profile принимает b.published и может установить видимость без проверки услуги/явно сохранённого рабочего графика. Текущий ProfileForm не посылает published и использует PATCH /profile/publication; поэтому проверенный UI-путь не затронут. Наличие прямого PUT published:true без service/schedule подтверждается также неизменённой начальной частью tests/address-save.test.mjs.

## Зависимости и разрешение

[U-10-02](U-10-02.md)

Ready разрешает начать анализ совместимости и подготовить конкретное изменение. Не менять legacy API молча и не восстанавливать бизнес-правила по одним тестам. Рекомендуемый вариант: изменение видимости только отдельным PATCH с общей проверкой готовности; определить совместимость прежних клиентов/fixture, сохранность скрытия и публикации, затем выполнить в отдельной задаче. Обнаружение в U-10-02 не означает разрешение выполнить всю очередь или production-выпуск.

Обычное сохранение описания/адреса не должно невольно открывать/скрывать страницу. Не ослаблять API ради старой fixture; отдельный UI-review нужен только при изменении поведения экрана.

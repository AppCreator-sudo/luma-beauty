## Граница задачи

14.10.2026 пользователь явно запросил передачу секретов и рабочих баз, чтобы облачный агент мог работать с сервером Luma Beauty. Это новое поручение после исходного GitHub-переноса. Оно не разрешает сейчас изменять приложение/UI или выполнять выпуск.

Подготовить доступ к серверу и нужную копию данных, зафиксировав фактический канал передачи. Секреты и приватные записи не выводить в чат/логи. Доступ к серверу и копирование базы в облачную разработку — разные операции.

## Зависимости и разрешение

[OPS-01](OPS-01.md) выполнена. Для внесения значений нужна выбранная cloud-среда из [OPS-03](OPS-03.md). Пока ожидаются два решения пользователя:

1. Права облачного агента: разработка/публикация или только просмотр/диагностика.
2. Копия для разработки: обезличенная или полная с реальными данными.

Запросы уже заданы в текущем чате. Не считать отсутствие ответа выбором. Не выдавать готовую инструкцию за реально подключённую среду.

## Порядок работы

1. Получить два решения выше, определить конкретную cloud-среду и способ доступа, поддерживаемый её сетью.
2. Подготовить согласованный доступ. Если используется отдельная учётная запись/ключ, проверить разрешённые операции и ограничение посторонних сервисов. Текущий локальный доступ сохранить.
3. Передать нужные значения через персональные настройки выбранной среды. Network secret относится к HTTPS-сервисам на 443; значение, которое процесс должен прочитать напрямую, задаётся соответствующей environment variable. Не выдавать HTTP-прокси за туннель SSH.
4. Для базы подготовить согласованный снимок через SQLite backup API; не копировать один файл живой WAL-базы. Проверить integrity/FK, происхождение/время и состав приватных данных. Рабочую базу не менять.
5. Если передаётся обезличенная копия: исключить действующие сеансы/ключи гостевой записи/контакты и проверить остальные связанные таблицы. Изменять только копию.
6. Передать копию отдельным закрытым каналом, при необходимости в зашифрованном контейнере. Для будущих агентов записать путь/способ получения без секретных значений. Не оставлять необработанные секреты в Git-истории.
7. Проверить доступ из настоящей cloud-задачи. Включить только согласованные права; не выполнять production-выпуск в качестве теста доступа.

## Приёмка

Указаны конкретная среда, принятый набор прав, защищённый способ передачи секретов/копии и реальные проверки доступа. Приложение/UI/production данные не изменены. Ключи и клиентские данные не попали в обычные документы/Git-историю. Готовность исходников и доступ к серверу отмечены отдельно.

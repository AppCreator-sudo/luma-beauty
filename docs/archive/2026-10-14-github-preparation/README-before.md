## Запуск

`npm ci`, `npm run build`, `npm test`, `npm start`. Локальный адрес http://localhost:3100.
Переменные — в `.env.example`; среда разработки использует `data/`. Node сам не читает .env: передавайте переменные через окружение либо `node --env-file=.env server.mjs`.

## Что работает

Регистрация по логину/паролю с обязательным выбором роли, отдельные кабинеты мастера и клиента, одноразовый код восстановления, серверные сессии, создание и публикация профиля мастера, услуги, фотографии с перекодированием в WebP, подписки, сохранённые работы, история посещений, подтверждённые отзывы и рейтинг, связь работы с услугой, отдельные ссылки на работы, заявки «Хочу так же» с визуальным референсом, ручные записи, подтверждение/перенос/отмена, защита пересечения подтверждённых записей, карта опубликованных координат, установка PWA, push-подписки, уведомления о заявках и напоминания за час.

Клиентские заявки не резервируют время до подтверждения. Время вводится в часовом поясе устройства, сохраняется UTC и показывается с указанием пояса. Карта использует OSM и показывается отдельным разделом. В пилоте до 100 публичных профилей в ответе: до масштабного запуска требуется пагинация/поиск по области карты. Отображение тайлов OSM нужно пересмотреть при росте трафика. Приложение не кэширует приватные данные и загрузки для офлайн-доступа; при отсутствии сети изменения не сохраняет.

## Публикации и лента

Работа содержит 1–6 фотографий. В редакторе можно добавить и убрать кадры, переставить их стрелками, выбрать обложку, изменить подпись и связанную услугу. Старые работы автоматически становятся публикациями с одним фото. В профиле можно закрепить до трёх работ и менять порядок внутри закреплённой или основной группы. В ленте `/feed` показываются работы опубликованных мастеров по подпискам, новые сверху; страницы загружаются по 12 публикаций.

Гость может отправить заявку без регистрации: имя, телефон России или Telegram @username, услуга и время. Вход до отправки остаётся добровольным. Данные заявки хранятся до двух часов в `sessionStorage` текущей вкладки. После добровольного входа восстанавливается форма с референсом; отправка требует отдельного нажатия. При выходе из аккаунта и успешной отправке черновик удаляется. Если браузер запрещает sessionStorage, форма сохраняется только до перезагрузки.

## Гостевая запись

`lib/guest-bookings.mjs` добавляет таблицу `guest_bookings` и API отправки, просмотра, отмены и привязки к аккаунту. Новая заявка имеет статус `pending` и не резервирует время до подтверждения мастера. Мастер видит контакт в календаре; SMS, проверка номера и автоматические уведомления гостю отсутствуют. После привязки к клиентскому аккаунту запись участвует в обычных уведомлениях и истории.

Личная ссылка имеет вид `/visit#<ключ>`: браузер создаёт 32 случайных байта, сервер хранит только SHA-256 ключа. Фрагмент URL не отправляется в HTTP-запросе страницы; API получает ключ в теле POST. Личная ссылка действует до 90 дней после текущего времени окончания визита и немедленно отключается после сохранения записи в аккаунт. По совпадению контакта привязка не выполняется. Повторная отправка неизменённого запроса с тем же ключом возвращает ту же запись без дубликата и повторного уведомления.

Ограничения: до 10 запросов создания в час с IP и до 3 гостевых заявок одному мастеру за сутки с одного нормализованного контакта; скрытое поле против простых ботов. Это базовая защита пилота, не подтверждение личности. Контакт доступен участникам записи и по личной ссылке, не включается в каталог или push.

Проверки: `npm test` проверяет права, повторы, квоты, отмену, перенос, привязку и отзыв. `node tests/guest-browser.mjs` на локальном `http://localhost:3101` проходит отправку без аккаунта, скачивание ссылки, подтверждение мастером, регистрацию после записи, сохранение в аккаунт и отзыв. Для проверки другой локальной среды задайте `TEST_ORIGIN`.

`lib/publications.mjs` содержит миграции и API публикаций. Проверки: `npm test` (включая права, атомарное изменение фото и пагинацию), `TEST_ORIGIN=http://localhost:3101 node tests/media-browser.mjs` (на локальном сервере: загрузка серии, редактор, обложка, закрепление, лента, регистрация и восстановление заявки). Для нескольких фотографий nginx должен разрешать запросы до 50 МБ; каждый файл ограничен 8 МБ, публикация — шестью файлами.

Демо: после первого запуска сервера с нужным `DATA_DIR` выполнить `node scripts/seed-demo.mjs` с тем же `DATA_DIR` (по умолчанию скрипт использует `.demo-data`). Нужны заранее сжатые файлы `media/mock-seed/01.webp`–`10.webp`, полученные из `mokuser`. На production требуется явный флаг `--allow-production-demo`. Скрипт создаёт только три помеченных примера, вход и запись у них отключены; настоящие аккаунты не изменяются.

## Социальный вход

Реализован адаптер Яндекс OAuth, кнопка видна только после задания YANDEX_CLIENT_ID и YANDEX_CLIENT_SECRET. Callback: `APP_ORIGIN/auth/yandex/callback`. Реальный вход через Яндекс требует регистрации приложения и проверки с полученными ключами. VK, Mail, ОК и Telegram не подключены; ключей владельца нет. Пароли и ключи сервера не хранить в репозитории.

## Уведомления

Пара VAPID создаётся при первом старте в DATA_DIR/vapid.json, сохраняется при обновлениях и резервируется вместе с базой. HTTPS обязателен. На iOS 16.4+ открывать установленную на домашний экран PWA. Разрешение запрашивается только по кнопке. Проверка «Отправить проверочное уведомление» сообщает о принятии push-сервисом; это не гарантия показа на устройстве. Реальную доставку на телефоне проверить отдельно. Push может зависеть от браузера, сети и настроек ОС. При выключенном сервисе напоминания не отправляются, просроченные не досылаются. В уведомления не включаются имена клиентов и услуги.

## Сервер

Новый проект: `/opt/atelie`, данные: `/opt/atelie/shared`, окружение: `/etc/atelie.env`, служба: `atelie.service`. Обновления размещаются в `releases`; `current` указывает на выбранный релиз. Старый `/opt/thegamepay` и PostgreSQL не удаляются. Резервируются конфигурация nginx и определения старых служб перед переключением. Временный адрес не индексируется.

Проверки: `npm test` проверяет настоящую БД, аккаунты, клиентскую медиатеку, работу-референс, загрузку фото, права доступа, CSRF, восстановление и конфликты времени. `tests/browser.mjs` проходит полный сценарий мастера и клиента на изолированном локальном сервере. `tests/smoke.mjs` выполняет read-only проверку опубликованного сайта.

Существующая пилотная версия не объявляется готовой к массовому привлечению пользователей.

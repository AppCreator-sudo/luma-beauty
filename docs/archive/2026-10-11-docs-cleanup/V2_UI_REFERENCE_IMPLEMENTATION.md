Если обнаружена недостающая функция/элемент, расхождение UI с эталоном, неоднозначность между макетами или конфликт с существующей функцией — сначала вынести конкретную проблему на обсуждение. Не добавлять, не удалять и не перестраивать спорную часть до ответа пользователя. Продолжать независимые согласованные части.

## Приёмка каждого экрана

1. Сравнить скриншот реализации с эталоном на одинаковом viewport: структура, пропорции, выравнивания, плотность, типографика, цвета, аватары и основные действия. Текст/фото берутся из реальных данных; длинные имена и пустые состояния также должны помещаться.
2. Проверить desktop и согласованный mobile, включая короткий экран: без наложений/горизонтального переполнения, цели касания не меньше 44 px, читаемые поля.
3. Выполнить сборку и один целевой сценарий изменённого экрана. Для изменения данных проверить сохранение/перезагрузку и права, для записи — соответствующий этап, для карты — синхронизацию точек/списка. Проверить ошибки и reduced-motion. Не повторять широкие тесты без причины.
4. Выпускать только завершённый сценарий после этих проверок, с резервной копией интерфейса и краткой проверкой сервера. Существующее разрешение пользователя на публикацию действует; новые спорные UI-решения это разрешение не заменяет.
5. Записать выполненное и оставшиеся вопросы в актуальную сводку. «Перенесён» означает рабочий, проверенный интерфейс, а не только изображение или стили.

- Не начинать общий аудит проекта, переписывание архитектуры или подбор новых инструментов ради локальной визуальной правки.
- Повторно использовать текущие компоненты и существующие подходящие проверки. Новые тесты нужны для содержательного изменённого поведения, а не для отступов или повторения реализации.
- Не выполнять широкий набор сценариев после каждого исправленного класса/отступа. Выполнять согласованный набор после готового блока; расширять проверки при сбое, новом изменении или конкретном неразрешённом риске.
- Не запускать дополнительные параллельные проверки без независимой полезной цели; для маленькой правки основной исполнитель ведёт её целиком.

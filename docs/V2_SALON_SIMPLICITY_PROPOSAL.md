# Простой кабинет салона — предложение 15.10.2026

Статус: **предложение для обсуждения, не реализация**. Пользователь попросил упростить назначения услуг/направлений и убрать путаницу между карточками мастеров и «Услуги и графики». [Кликабельный макет](ui-concepts/2026-10-15-salon-simplicity/index.html), [desktop/mobile и проверки](ui-concepts/2026-10-15-salon-simplicity/README.md), [U-10-19](tasks/U-10-19.md).

## Почему сейчас возникает путаница

По действующему коду `SalonOwnerCabinet.tsx` услуги/графики редактируются и внутри «Команды», и в «Услуги и графики». Общий выбранный сотрудник и его вкладка используются между разделами. В `StaffSetupForm.tsx` доступные услуги собираются из услуг сотрудников; ключ — название/цена/длительность. В `lib/workspaces.mjs` назначение создаёт или сохраняет отдельную строку services у исполнителя. Изменения копии не являются изменением единого салонного прайса. Направления профиля и услуги отмечаются отдельно. Поэтому одной перестановки кнопок недостаточно для единого источника данных.

## Предлагаемый порядок

**Направление → услуга салона → исполнители → рабочий график.** Направление — понятная группа прайса («Маникюр», «Брови»), услуга — конкретное предложение с ценой и длительностью. Выбирая исполнителей у услуги, владелец сразу назначает её нескольким людям.

| Раздел | Что пользователь делает | Как избежать дублей |
| --- | --- | --- |
| Услуги | Один прайс по направлениям, поиск, добавление/изменение услуги, назначение мастерам | Убрать выбор мастера как обязательное первое действие; фильтр по мастеру появляется при переходе из его карточки |
| Мастера | Имя, фото, сведения; видны направления, число услуг и готовность графика | «Данные» редактирует профиль; «Услуги», «График», «Работы» открывают соответствующий раздел с этим мастером |
| Календарь | Две явные вкладки: «Записи» и «Рабочие графики» | Один редактор рабочих часов/циклов; карточка мастера ведёт в него, сохраняя контекст |
| Публикации | Публикации салона / работы выбранного мастера | Переход из мастера сразу фильтрует автора; фиксированный автор и действующий редактор сохраняются |

Существующие «Обзор», «Страница салона», «Архив», «Настройки», публичная шапка и мобильное меню сохраняются. Макет показывает только изменяемые связи; четыре демонстрационных пункта не означают удаление остальных.

## Сценарии без лишних поисков

1. **Добавить услугу.** «Услуги» → «Добавить услугу» → направление, название, цена от, длительность → галочки исполнителей → «Сохранить». После сохранения видно, кто оказывает услугу. Услуга без исполнителя сохраняется, но не предлагается для онлайн-записи.
2. **Назначить готовую услугу нескольким мастерам.** Открыть услугу → отметить сотрудников → сохранить. Не создавать ту же услугу заново внутри каждого профиля. «Назначить всем» не включается автоматически.
3. **Проверить одного мастера.** «Мастера» → карточка с именем → «Услуги · 7» → общий прайс с видимым фильтром «Услуги мастера: Алина» и действием «Показать весь прайс». Изменение услуги открывает тот же редактор.
4. **Настроить график.** «График» у мастера → «Календарь / Рабочие графики» с уже выбранным именем. Действующие 2/2, 3/3, выбранные дни недели, произвольный цикл и исключения сохраняются. Назад возвращает предыдущий контекст.
5. **Добавить сотрудника.** Имя/фото → выбрать услуги по направлениям → настроить график. Можно сохранить черновик; до фото, обязательных данных, подходящих услуг и графика онлайн-запись не включается. Условия готовности не ослабляются.

## Направления, цены и длительность

- Для новых назначений направления салонного мастера выводятся из его услуг: не заставлять отмечать одно направление второй раз в отдельной форме. Направление услуги выбирается явно один раз. Это предложение для салонных назначений; самостоятельный мастер не переводится в салонную модель.
- В услуге — базовые цена и длительность. Одинаковые условия у всех исполнителей не требуют дополнительных полей. При различиях раскрывается «Особая цена или время у мастера», пустое значение означает базовое. Существующие различия при переходе сохраняются.
- Перед сохранением общей цены/времени видно, на каких мастеров повлияет изменение. Индивидуальные условия не перезаписываются молча. Это тот же единый редактор, дополнительная копия формы не появляется.
- Клиент видит доступное предложение и цену конкретного исполнителя; разные длительности нельзя рассчитывать по общему кратчайшему слоту. Цена «от» вычисляется из действующих предложений. Выбранные услуга/исполнитель/время повторно проверяются сервером перед записью.
- Старые направления без связанной услуги не удаляются автоматически: сначала список соответствий для владельца. Направление нельзя потерять из каталога/работ при техническом переходе.
- Снятие услуги с мастера прекращает новые записи на неё; ранее оформленные визиты и привязки работ сохраняются. Удалять строки с историческими ссылками ради упрощения UI нельзя.

## Границы модели и безопасный переход

Нужен общий каталог определений услуг салона и связь с исполнителями. Точные таблицы/API согласуются при реализации; это не разрешение мигрировать рабочую БД сейчас. Существующие services.id и ссылки работ/записей сохраняются. При переносе вначале строится отчёт соответствий: одинаковые название, направление, цена и длительность могут быть кандидатами на объединение, разные условия/пустое направление требуют явного решения. Совпадение только названия не считается достаточным.

Салонное редактирование — в пределах действующих прав владельца. «Менеджер» остаётся UI-подписью, новый тип серверного доступа не создаётся. Сотруднику не добавляется несуществующее право самостоятельно менять салонный прайс. Если нужен отдельный вход управляющего/сотрудника, это отдельное решение о правах.

## Как внедрять после согласования

1. Зафиксировать эту структуру и правила отличающихся цен/направлений; при необходимости поправить макет. Утверждённая цветовая и типографическая концепция сохраняется.
2. На отдельной базе подготовить единый каталог/назначения и совместимый переход с сохранением IDs, исторических визитов, работ и различий условий. Проверить отчёт соответствий и повторный запуск миграции.
3. Перенести «Услуги», связать карточки «Мастеров», перенести рабочие графики в календарь. Удалить дублирующие редакторы после переключения всех ссылок. Не оставлять два конкурирующих способа создавать услугу.
4. Проверить новый салон без услуг/сотрудников, существующий салон с разными ценами, несколько направлений, снятие назначения, архив сотрудника, параллельное редактирование, цикл/исключение, обычную/гостевую запись, ближайшее окно и Back; desktop/mobile вместе. Публикация — после проверки и явного поручения.

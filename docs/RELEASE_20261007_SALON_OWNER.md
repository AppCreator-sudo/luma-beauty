# Салон v2 — команда внутри салона и управление владельцем

Опубликовано 7 октября 2026, Новосибирск: серверный выпуск `20261007-v2-salon-owner` (00:15:13), frontend `20261007-v2-salon-team-mobile` (00:24:44). Публичная страница: https://atelie-13-143-66-1.sslip.io/v2/s/saloon.

## Итоговое поведение

- Общий каталог показывает салоны и индивидуальных мастеров. Отдельные карточки сотрудников убраны; поиск имени сотрудника возвращает салон с подписью совпадения. Категория и ближайшее время считаются по соответствующим услугам команды.
- На странице салона компактные карточки сотрудников с одним круглым портретом. «Работы» выбирает автора в галерее внутри салона, «Записаться» передаёт его в существующую запись. Пустое портфолио имеет понятное состояние.
- Салон и его команду ведёт владелец. Проверки доступа находятся на сервере; выдача и принятие приглашений сотрудникам закрыты. Старые связи аккаунтов с сотрудниками сохранены для общей занятости; визиты и история не удалены.
- Добавление/редактирование мастера: одна форма фото, имени, направлений, рабочих дней/часов и услуг. Для показа дополнительно нужна услуга с ценой и длительностью. Список существующих услуг можно назначать без ручного повторения, график — копировать у коллеги. Черновик сохраняется скрытым. Пустые дни действительно сохраняются пустыми, отключая новый приём. Время сотрудника определяется салоном.
- Одна форма публикаций с выбором «Салона / мастер». Работа мастера хранится один раз и показывается в его портфолио и галерее команды. Салонные публикации имеют виды «Интерьер и атмосфера» и «Новость салона», идут в «Жизнь салона» и не смешиваются с работами в общей ленте вдохновения. Редактирование сохраняет автора; фотографии можно оставить или заменить. Владелец может удалять публикации.
- Скрытие сохраняет календарь, услуги и работы; архивирование остаётся отдельным действием. Фото, сохранение графика и готовность новых карточек проверяются сервером. Ранее опубликованные сотрудники без фотографии сохраняют прежний показ до завершения данных владельцем; при новом включении показа фото обязательно.

Пользователь разрешил самостоятельно придумать содержание на основе существующего мастера; имена и предложения услуг не утверждаются как сведения о реальных специалистах.

Новые работы с выдуманными результатами не добавлялись.

## Проверки по изменённым сценариям

TypeScript/Vite: успешно. Два целевых теста `tests/salon-owner-flow.test.mjs`: миграция/повтор и полный маршрут владельца с обязательными полями, копированием услуги, сохранением/очисткой графика, публикацией, поиском сотрудника, публикациями/редактированием, выбранным мастером, отказом при занятом времени, правами другого владельца/бывшего сотрудника и сохранением истории при скрытии. Полный прежний набор не запускался; старые проверки приглашений описывают прежнюю модель доступа.

Короткая проверка браузером: завершение черновика с фото и скопированным графиком через форму, сохранение после перезагрузки, редактирование публикации, портфолио выбранного автора в салоне, ширины 1440/390/320. Формы и публичная команда не создают горизонтального переполнения. По итоговому виду исправлено влияние старого оформления карточек на отступы компактной команды. На экране 320 px также устранена прежняя минимальная ширина body: ширина страницы равна доступной ширине без вертикальной полосы, поэтому нижняя горизонтальная прокрутка отсутствует.

На сервере подтверждены active-служба, health `ok`, текущие HTML/JS/CSS/service worker, две карточки общего каталога без дублей сотрудников, шесть сотрудников публичного салона, поиск Полины, время пяти новых мастеров и 401 для анонимного доступа к публикациям кабинета. Рабочие фикстуры и тестовые фото не переносились.

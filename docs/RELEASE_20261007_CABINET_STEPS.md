# Пошаговые формы и компактные блоки кабинетов v2

Опубликовано 7 октября 2026, 20:14:51 по Новосибирску (13:14:51 UTC). Frontend `20261007-v2-cabinet-steps`, серверная основа `20261007-v2-inspiration-visibility`.

## Поведение

- Запись клиента в календарях индивидуального мастера и сотрудника салона: клиент/услуга → время → итог и заметка → одно сохранение. При возврате имя, услуга, дата, время и заметка сохраняются. Время записи вычисляется по часовому поясу мастера/салона; индивидуальный календарь показывает созданный визит на соответствующем дне. Перерыв остаётся прямой короткой формой.
- Новый сотрудник: фото/имя/направления → услуги/график → итог. Фото хранится в состоянии формы и сохраняется при возврате. Есть явное сохранение скрытого черновика. Редактирование готового сотрудника осталось прямым; обязательные поля, видимость и серверные проверки сохранены.
- Новая работа/публикация: автор/услуга либо вид публикации → фото → подпись/итог. Общий компонент применяется в салоне и индивидуальном портфолио. Файлы и поля остаются при возврате; итоговый POST выполняется по «Опубликовать». Отдельная кнопка создания услуги остаётся явным самостоятельным действием. Редактирование публикаций прямое.

Шаги не превращают короткие ежедневные действия в дополнительные экраны. Проверка текущего шага происходит до перехода; финальная отправка повторно проверяет данные и защищена от повторного нажатия. Ошибка обновления списка после сохранения не предлагается как повторное создание записи или публикации.

Рабочие шапки кабинетов теперь компактные: аватар, имя, статус и оформление без большой декоративной обложки. Уменьшены отступы, уплотнены блоки команды, календаря и формы; пустой предпросмотр скрыт на первом шаге публикации, выбранное фото показывается целиком в ограниченном по высоте предпросмотре. Крупное оформление публичных страниц сохранено. Названия шагов на телефоне располагаются под номерами, без разрыва слов ради узкой колонки.

## Проверка

TypeScript/Vite и синтаксис service worker прошли. Проверены целевые браузерные сценарии на закрытой локальной копии: пустые обязательные поля, отсутствие раннего POST, возврат с сохранением данных и фото, создание записи сотруднику, конфликт занятого времени `409` с сохранением формы, прямой перерыв, создание готового сотрудника, публикация для сотрудника, запись и работа индивидуального мастера. На экранах 1366 и 320 px проверены формы публикаций и сотрудника, отсутствие горизонтального переполнения и кнопки действий не меньше 44 px. В отдельной проверке мобильная шапка салона занимала 150,44 px. Консоль в завершённых сценариях без ошибок. После функциональной проверки выполнена небольшая CSS-правка размещения подписей шагов и финальная сборка.

Проверка обнаружила и до выпуска устранила преждевременную отправку публикации: React мог переиспользовать кнопку «Далее» как submit-кнопку в том же клике. Теперь кнопки имеют разные ключи, а переход отменяет действие события. Повторный сценарий с уже заполненной подписью подтвердил отсутствие POST до финальной кнопки. Технические ошибки селекторов/подготовки тестового аккаунта исправлялись в локальном проверочном скрипте; рабочие данные при этом не затрагивались. Широкий набор тестов не запускался.

После публикации проверены актуальные HTML, JS/CSS кабинетов, service worker, health `ok` и `active`. Модель данных, серверные права, проверка пересечения записей и опубликованная главная сохранены. Тестовые аккаунты, сотрудники, записи, публикации и фотографии на сервер не переносились.

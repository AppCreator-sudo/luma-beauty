## Согласованные решения 14.10.2026

1. **Полоса фильтров:** в map.png город/услуга/день. Фактически есть общий поиск, направление и ближайший час; произвольного дня в API нет. Предложение — использовать действующие три функции, как показано в review.
2. **Рейтинг/километры/цена «от»:** `MapMaster`/viewport не возвращают рейтинг или минимальную цену, расстояние не вычисляется. Не дописывать серверные функции в UI-этапе; убрать эти строки, цену реальной услуги оставить в выбранной карточке. Это относится и к мастерам, и к салонам на карте, не удаляет отзывы из публичных профилей.
3. **Переключатель:** предлагается переключение вида этой же карты, с её областью/фильтрами/результатами. Это не переход на общий `/masters`, у которого другой набор данных. На телефоне два вида вместо карты и списка друг под другом. На desktop список может занять ширину рабочей области без изменения запроса.
4. **Данные записи и состояния:** добавляем в выбранную карточку имеющиеся данные ближайшего окна и состояния из матрицы. Master/salon равноправны, сотрудники не отдельными точками; у салона сотрудник только у найденного времени.

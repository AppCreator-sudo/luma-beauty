# Кабинет владельца салона — предложение макетов

Подготовлено и **утверждено пользователем 10 октября 2026 года**, реализовано и опубликовано выпуском `20261010-v2-salon-cabinet-reference`. Проверки: [аудит](../../../V2_SALON_CABINET_REFERENCE_AUDIT.md), [отчёт выпуска](../../../RELEASE_20261010_SALON_CABINET_REFERENCE.md). Основа — утверждённые cabinet-review-01 desktop/mobile. Исходные эталоны не изменяются. Данные и фотографии на изображениях иллюстративные, в рабочую базу не добавляются.

Уточнение при утверждении: название в интерфейсе — **«Менеджер»**, вместо «Старшая салона». Это название управляющего в UI, а не новая роль доступа: существующие полномочия владельца и управление только владельцем сохраняются. Подпись роли на макетах «Владелец» при переносе заменить на «Менеджер»; остальные элементы утверждены без изменения.

## Полный состав кабинета

| Раздел | Действия и данные | Размещение |
| --- | --- | --- |
| Обзор | Дата, записи команды, заявки на подтверждение, мастер каждой записи, перерывы, ближайшие свободные окна, готовность страницы | Основная панель + узкая колонка команды/страницы; на телефоне одна колонка |
| Календарь | Дата, поиск/выбор мастера, заявки, создание записи или перерыва, подтверждение/завершение/отмена, контакт и заметки | День команды: время по вертикали, сотрудники по горизонтали; на телефоне список дня с фильтром мастера |
| Детали и редактирование записи | Имя клиента, услуга, дата/время, длительность, цена, заметки; контакт заявки только для просмотра | Панель справа на desktop, отдельный экран на mobile; использовать утверждённые поля редактора календаря |
| Команда | Поиск, статусы виден/скрыт/черновик, добавление, редактирование, показ клиентам, переход к календарю/услугам/графику/работам | Компактные строки с круглым портретом, выбранный мастер рядом; на телефоне список → карточка |
| Создание мастера | Фото, имя, категории; услуги с ценой и длительностью; рабочие дни/часы, копирование графика коллеги; проверка и черновик | Три шага: Карточка → Услуги и график → Проверка; поля ограниченной ширины |
| Услуги и графики | Услуги конкретного сотрудника, цена, длительность, назначение из имеющегося списка; рабочие дни, часы, часовой пояс салона | Единый вход с выбором сотрудника, два подраздела; не смешивать разные цены одного названия |
| Публикации | Адресат салон/сотрудник, фото, подпись; услуга для работы мастера; интерьер/атмосфера или новость для салона; редактирование/удаление | Галерея + единая пошаговая форма Фото → Описание → Проверка; четыре колонки desktop, две mobile |
| Страница салона | Логотип, обложка, название, адрес страницы, описание, точный адрес, часовой пояс, публикация/скрытие, предпросмотр, публичная ссылка | Оформление / Данные / Адрес; адрес сохраняется отдельно, как в текущем сценарии |
| Архив | Архивирование после разрешения будущих визитов, передача подходящему мастеру/отмена с согласованием клиента, просмотр истории, возвращение сотрудника | Отдельный раздел; не заменять скрытие удалением |
| Настройки | Вход и безопасность, уведомления в рамках доступных функций, выход; переключение салона при нескольких рабочих местах; личная практика для существующей соответствующей роли | Настройки и меню профиля; без общих паролей и новых полномочий сотрудников |
| Общая навигация | Мастера, Вдохновение, Карта, существующий поиск каталога, публичная страница/поделиться | Та же шапка и логотип, что у утверждённого кабинета мастера; mobile меню по кнопке |

## Правила и ограничения реализации

- Управляет владелец. Старые связи аккаунтов сохраняются для данных и занятости; выдача сотрудникам управления не предлагается.
- Обязательны фото, имя, категории и явно сохранённый график. Для онлайн-записи также требуется назначенная услуга. Черновик скрыт от клиентов.
- Скрытие сотрудника сохраняет его данные и текущие записи. Архив — отдельная процедура с проверкой будущих визитов.
- У каждой записи, перерыва и свободного окна явно указан сотрудник. Перерыв в обзоре не может показываться без владельца времени.
- Заявки в отдельном блоке не ограничивать выбранным днём; показывать собственную дату заявки, не дублировать её ошибочной датой в списке дня.
- Ближайшие окна вычислять по реальным услугам, расписанию и занятости. Визуальные числа не копировать в интерфейс.
- Назначение услуг через общий вход не означает новый независимый прайс-лист в базе: сохраняется модель услуг исполнителя.
- Полное редактирование записей салона в новом UI необходимо подключить и проверить отдельно. Возможность серверного обработчика не означает уже перенесённый интерфейс салона.
- Недельный/месячный обзор всей команды не добавлен этим предложением: текущий день команды и индивидуальные календари сохраняются. Если нужны дополнительные режимы всей команды, сначала согласовать вид и поведение.
- Загрузки используют существующие ограничения из `frontend/src/lib/imageUpload.ts`; подсказки размеров/форматов сохраняются. Не брать случайные цифры из генерации.
- Нет новых финансовых отчётов, клиентской CRM, чата, помещений, ручных напоминаний или верификации.
- Mobile: одна колонка, фильтр сотрудника вместо широкой матрицы, меню по кнопке, доступные области касания ≥44px, без горизонтального переполнения страницы. Действия не перекрывают поля и клавиатуру.
- Растровые изображения показывают композицию; эта спецификация определяет точные поля, права, статусы и редкие состояния. Ошибки текста и данных генерации не являются требованиями.

## Состояния, обязательные при переносе

Новый салон без команды; незаполненная страница; мастер без фото/услуг/графика; черновик; скрытый мастер; пустой день/нет свободных окон; архив пуст/есть будущие визиты; загрузка; ошибка сохранения с сохранением полей; конфликт времени; устаревшая запись; длинные имена и названия; подтверждение удаления/отмены; успех сохранения; уменьшение движения.

Код, рабочая база и production фиксацией не меняются. Изображения и спецификация с уточнением «Менеджер» являются отдельным утверждённым эталоном кабинета салона; спорные новые элементы обсуждаются до реализации.

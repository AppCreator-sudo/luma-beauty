## Продукт и роли

Luma Beauty — бьюти-площадка: поиск мастеров/салонов, работы, карта, запись, управление услугами/графиком/визитами, личный кабинет клиента. Разработка **только v2**: `frontend/`, `server.mjs`, `lib/`. `public/app.js` и v1 не источник текущего UI.

- **Клиент**: гостевая или авторизованная запись, свои визиты, запрос переноса с подтверждением, отмена/отзыв, сохранённое/подписки, уведомления, необязательные приватные данные, безопасность/экспорт.
- **Самостоятельный мастер**: публичная страница, услуги, портфолио, рабочий график и свои записи.
- **Владелец салона**: команда, услуги/графики, публикации, страница салона и визиты. «Менеджер» — подпись владельца в UI, не новая серверная роль.
- **Сотрудники салона** внутри салона, не отдельными карточками общего каталога. Новые собственные кабинеты/приглашения сотрудникам не вводятся; старые связи/аккаунты сохраняются совместимо.

Мастер и салон равноправны. Для готовности сотрудника нужны фото, имя, категории и сохранённый график; для записи — услуга с ценой/длительностью.

Площадка не принимает оплату услуги между клиентом и мастером и не берёт комиссию за клиента/визит. Будущая добровольная монетизация продвижением — отдельное продуктовое решение F-12, не разрешение встроить оплату записи.

## Визуальный договор и навыки

**Утверждённый UI = внешность реализации.** Точный источник для каждого экрана — [UI-журнал](V2_UI_REFERENCE_IMPLEMENTATION.md). Базовые PNG от 10 октября и уточнения от 10–11 октября нельзя перезаписывать. Новое уточнение сохранять отдельным review с решением пользователя.

| Тип задачи | Прочитать навык | Для чего |
| --- | --- | --- |
| Сверка функций, компоновка, недостающие desktop/mobile, обсуждение | [atelier-v2-product-design](../.agents/skills/atelier-v2-product-design/SKILL.md) | Подготовить согласуемый вариант в принятой системе |
| Перенос, исправление UI, адаптация, анимации | [atelier-v2-ui-implementation](../.agents/skills/atelier-v2-ui-implementation/SKILL.md) | Сохранить функции/данные и проверить реальный внешний вид |
| Backend/миграция | Текущая спецификация и тесты карточки | Специального проектного backend-навыка сейчас нет; UI-навык не разрешает изменение архитектуры |

Для создания bitmap-медиа дополнительно нужен доступный системный `imagegen` и его SKILL.md; он не заменяет редактирование существующего SVG/кодового логотипа. Не устанавливать новые навыки автоматически ради каждой задачи. Прямые решения пользователя и AGENTS имеют приоритет над более общими/старыми фразами навыков.

Общий стиль: зелёный, молочный, бордовый, золото; существующая шапка/ветка/пружинное меню. Главная сохраняет собственную полноэкранную композицию. Во всех v2 по итогу не остаётся старых элементов и нижней навигации. Desktop/mobile вместе: круглые аватары, действия от 44 px, reduced-motion, без переполнения/наложений.

## Данные, адрес и проверки

Сейчас **SQLite и Leaflet/OpenStreetMap**. Они не меняются под видом UI. PostgreSQL/PostGIS/чат — будущие задачи. Точный адрес не заменять соседним домом; отсутствие результата провайдера не доказывает вымышленность дома. Не добавлять платную DaData. Правила фото — [image-rules.json](../lib/image-rules.json).

Для бизнес-операций использовать отдельную тестовую базу, не вводить вымышленные данные в production. Не читать/печатать SSH-реквизиты, токены, private fixtures в документацию. Сохранять гостевую запись, права и старые данные.

- UI: `npm.cmd --prefix frontend run build`, затем `npm.cmd run build` и целевой браузерный проход desktop/mobile.
- Данные: целевые тесты карточки + save/reload/права/повтор/конфликт на отдельной базе. Сборка не доказывает внешний вид и сохранение данных.
- Не повторять полный набор без причины. Для документации достаточно проверки ссылок/карточек/зависимостей/сохранности эталонов; сборка приложения не нужна.
- Настоящий OS-свайп и push-доставка требуют физического устройства. Не выдавать браузерную имитацию за такую проверку.

## Выпуск и фиксация результата

Состояния **«согласовано» → «сделано локально» → «проверено» → «опубликовано»** различаются. Даты только фактические, Asia/Novosibirsk; неизвестное оставлять пустым, будущие сроки не придумывать.

Перед выпуском проверить фактический сервер и действующее разрешение. Пользователь разрешал проверенные UI-выпуски и отдельно U-08C; это не разрешает новую архитектуру/миграцию/удаление данных. Для такого изменения подготовить конкретный результат/откат до запроса разрешения. Сохранять shared, data, uploads и private-client; локальные тестовые базы не отправлять на сервер.

Для текущего U-08C допустим только [совместимый откат r2](RELEASE_20261011_CLIENT_CABINET_REFERENCE.md), без удаления новой схемы/приватных фото или возврата старой базы поверх новых записей.

По завершении обновить карточку и [registry.json](tasks/registry.json), выполнить `python -X utf8 docs/tasks/update-index.py`, затем [checkpoint](WORK_CHECKPOINT.md), [state](CURRENT_STATE.md), [roadmap](PROJECT_ROADMAP.md); UI — [журнал](V2_UI_REFERENCE_IMPLEMENTATION.md), фактический выпуск — отдельный RELEASE.

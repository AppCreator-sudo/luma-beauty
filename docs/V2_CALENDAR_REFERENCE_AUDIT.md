# Календарь по эталону — согласования и реализация

Согласования и проверки завершённого этапа [U-04](tasks/U-04.md) сохранены ниже; [отчёт выпуска](RELEASE_20261010_CALENDAR_REFERENCE.md) подтверждает публикацию 10.10.2026 19:47:27 Новосибирск. Актуальная очередь — [карточки задач](tasks/README.md). Проверки ниже относятся к выпуску U-04, не к новой проверке рабочего сервера.

10 октября 2026. Исходный эталон: `ui-concepts/2026-10-10-luma/calendar.png`; мобильное уточнение: [calendar-review-01](ui-concepts/2026-10-10-luma/calendar-review-01/README.md).

Пользователь утвердил удаление отсутствующих в данных помещений/настройки напоминаний, сохранив автоматические уведомления. Потребовал полноценное редактирование вместо одного переноса. Затем утвердил мобильные макеты и поля: имя, услуга, дата/время, длительность, цена, заметки; контакт заявки только для просмотра. Утвердил дневную шкалу, недельный список и компактный месяц на mobile; недельную сетку desktop. Шапка и навигация используют уже согласованную систему кабинета.

Реализация использует реальные записи и часовой пояс мастера. Время начала определяет положение блока, длительность — высоту; очень короткие события имеют визуальный минимум для управления, при этом точное время показано текстом. Пересекающиеся видимые события раскладываются по колонкам. Отменённые записи освобождают сетку. Редактирование активных записей сохраняет все поля одной транзакцией, проверяет занятость и устаревший снимок. Изменение услуги не меняет общий прайс-лист. Сторонний пользователь не редактирует запись; профессиональный редактор недоступен клиенту. В выпуске U-04 клиент мог отменять свою запись. После опубликованного [U-08C](tasks/U-08C.md) клиент также запрашивает новое время в своём кабинете: перенос требует подтверждения мастера/владельца, исходный визит действует до принятия запроса. [Спецификация переноса](V2_CLIENT_CABINET_REFERENCE_AUDIT.md), [выпуск U-08C](RELEASE_20261011_CLIENT_CABINET_REFERENCE.md). Гостевой контакт/ключ доступа не изменяются профессиональным редактором.

Новая запись сохраняет текущую пошаговую форму. При повторном открытии поля сбрасываются. Перечитывание данных не размонтирует календарь: выбранная дата и подтверждение сохраняются, повторная загрузка доступна без повторного создания записи. Шапка, боковое меню, поиск, share и переходы согласованы с кабинетом.

Проверено: сборка TypeScript/Vite, новый тест атомарного редактирования, два теста расписания, интеграционный жизненный цикл гостевой записи, отдельная браузерная проверка API/UI на изолированной SQLite. Шесть размеров 1586×992 / 1366×768 / 1024×768 / 800×900 / 390×844 / 320×568; без горизонтального переполнения и ошибок JS. Полное редактирование/reload, конфликт и откат, права, stale-save, день/неделя/месяц, создание/reload, переходы навигации. Физический телефон и авторизованный production-сценарий не проверялись.

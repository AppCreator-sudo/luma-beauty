# BUG-008 — удаление услуг и работ мастера

Дата проверки: **15.10.2026, Asia/Novosibirsk**. Результат: **61/61 проверка после исправления**, без необработанных ошибок JavaScript. Проверены desktop 1440 px и mobile 390/320 px. Это локальная приёмка исправления BUG-008; публикация на рабочем сайте не выполнялась.

Проверка использует новую синтетическую SQLite в отдельной `.cache/bug008-deletion-*`, локальный сервер `http://localhost:3262`, существующий тестовый поставщик точного адреса и изображения PNG, созданные через `sharp` с учётом `lib/image-rules.json`. Рабочие данные, конфигурация сервера и настоящие секреты не использовались. Данные формы регистрации и коды восстановления в отчёты не записываются. После проверки сервер остановлен (`fixtureStopped: true`).

## Что проверено

На каждой из трёх ширин для собственной услуги без связанной работы и собственной работы:

1. Отмена стандартного подтверждения отправляет **0 DELETE** и сохраняет объект.
2. Ответ DELETE 500 показывает видимую ошибку `role="alert"` у нужного объекта, сохраняет объект в интерфейсе и БД, возвращает доступность кнопки.
3. Разрыв сети показывает новую ошибку, сохраняет объект и позволяет повторить удаление.
4. Две синхронные активации кнопки до следующей отрисовки React при удерживаемом запросе отправляют **1 DELETE**; кнопка заблокирована до ответа.
5. Следующая попытка выполняет настоящий DELETE 200. Удалённый объект исчезает из списка и БД; результат сохраняется после полной перезагрузки страницы.
6. Дополнительный GET `/api/studio` 500 после подтверждённого DELETE не возвращает удалённый объект в интерфейс. Сообщение об успешном удалении остаётся видимым. «Повторить обновление» успешно обновляет список без второго DELETE.
7. Существующая запись клиента сохраняется без изменений, в том числе после удаления услуги, по которой она создана. Полный кабинет другого мастера и его запись сохраняются без изменений.

Также на каждой ширине проверены настоящий **409** для услуги, связанной с оставшейся работой, и существующие границы API: попытка удалить чужую услугу отвечает 200 без удаления; чужую работу — 404. Серверные обработчики, разрешения и схема данных не менялись.

В 15 итоговых снимках автоматическая проверка подтвердила отсутствие горизонтального переполнения и размеры кнопок удаления **44 × 44 px**. Все 15 снимков просмотрены визуально: текст ошибок читается целиком, не перекрывает действия и не обрезается на ширине 320 px. Сохранены композиция кабинета, цвета, типографика и сетка утверждённой реализации.

## Воспроизведение до исправления

До новой frontend-сборки отдельный запуск на 390 px воспроизвёл обе исходные ошибки: по одному DELETE 500, объект остаётся, видимого `role="alert"` нет, возникает необработанное отклонение Promise (`pageerror`). **5/5 подтверждений воспроизведения** находятся в [before-fix-report.json](before-fix-report.json); снимки — [услуга](before-fix-service-missing-error-390.png) и [работа](before-fix-work-missing-error-390.png).

## Повторный запуск

После сборки frontend выполнить из корня проекта:

```powershell
node scripts/verify-master-deletion.mjs
```

Скрипт [verify-master-deletion.mjs](../../../scripts/verify-master-deletion.mjs) создаёт новую изолированную БД при каждом запуске, блокирует внешние запросы браузера и останавливает дочерний сервер в `finally`. Для воспроизведения исходного дефекта на старой frontend-сборке предусмотрен `LUMA_DELETION_BEFORE_FIX=1`; на исправленной сборке этот режим ожидаемо не проходит.

Граница проверки: услуги и работы самостоятельного мастера в `/v2/studio`; остальные кабинеты и экраны не объявляются принятыми этим отчётом.

Документация проверена неизменённой логикой `scripts/validate-docs.py` с read-only инвентарём tracked и ещё не добавленных, не игнорируемых файлов (`git ls-files --cached --others --exclude-standard -z`). Это проверяет новые отчёты/карточки до коммита; сам валидатор не изменялся. Результат сохранён в `documentation_validation` отчёта.

# BUG-018 — стабильное переключение входа и регистрации

Проверка 18 октября 2026, Asia/Novosibirsk. Пользователь сообщил о смещении элементов `/v2/auth` при выборе «Войти» / «Создать аккаунт».

Эталон: [утверждённый auth review-02](../../ui-concepts/2026-10-11-luma/auth-review-02/README.md). Проверка сохраняет орнамент, цвета, типографику, три действующие роли и недоступные внешние провайдеры «Скоро». Прикреплённые пользователем снимки с личным логином в репозиторий не копировались.

Воспроизведение: `AUTH_LAYOUT_BEFORE=1 node scripts/verify-auth-layout-stability.mjs`. Итоговая приёмка: `node scripts/verify-auth-layout-stability.mjs`. На Windows переменная режима задаётся отдельно через `$env:AUTH_LAYOUT_BEFORE='1'`; для итоговой приёмки её следует удалить или установить `'0'`.

## Граница проверки

Новый локальный процесс, отдельная пустая SQLite в `.cache/`, браузер Chrome. К локальному серверу проходят только GET/HEAD. Для двух дополнительных снимков recovery перехвачены две синтетические отправки `/api/auth/register`: ответ сформирован внутри браузера, запросы не переданы серверу. В финальном прогоне `clipboard.writeText` заменён браузерной заглушкой; проверка текста «Код скопирован» не вызывает системный буфер. Остальные отправки форм и обращения наружу заблокированы. Рабочий сервер, аккаунты, записи, фотографии и секреты не используются. Оригиналы утверждённых PNG не изменяются. Runner завершает браузер и тестовый сервер в `finally`.

## Финальная приёмка

**96/96 PASS**, frontend `index-D4kBlu6Z.js`; [итоговый отчёт](after/report.json). Визуальный контроль: **16 основных PNG и2 новых PNG клавиатурного фокуса**. Необработанные JS-ошибки0, горизонтальное переполнение0, действия не меньше44px. Тестовый процесс остановлен; SQLite integrity/FK PASS, созданных аккаунтов0, реальных отправок регистрации/входа0. Настоящая регистрация/вход и серверная обработка recovery этим косметическим этапом заново не проверялись.

Верх заголовка и описания, их размеры и рамка intro, вкладки и левая композиция остаются на месте во всех пяти размерах. Критерий геометрии — не более1px; измеренные смещения в финальных основных парах равны0.

**Мобильная граница:** три вертикальные кнопки ролей занимают160px плюс20px нижнего отступа. На телефоне их место в режиме входа не резервируется: при регистрации раскрывается только этот блок, нижние поля смещаются ровно на180px. Это не проверка «все элементы mobile имеют нулевое смещение». При обычном motion раскрытие занимает180ms, при `prefers-reduced-motion` переход отключён. Положение вкладок/intro/орнамента и scrollY при настоящем нажатии остаются стабильными. На desktop место ролей68px сохраняется в обоих режимах.

Проверены также три действующие роли и единственный активный выбор, отсутствие скрытых ролей в accessibility tree и Tab-порядке входа, сохранение текста полей/показа пароля, `current-password`/`new-password`, три повторных переключения, Back/Forward, обычный и reduced motion. Клавиатурный Tab к первой роли на1440/390 показывает золотой outline2px, offset−4px: рамка целиком внутри кнопки и не обрезается accordion-контейнером. В двух дополнительных размерах проверены ошибка провайдера и её очистка при переключении, уже выполненный вход и recovery с копированием синтетического кода через заглушку. Recovery и signed-in не получают резерв ролей.

[Промежуточный отчёт](intermediate-report.json), frontend `index-Cz4dkW-c.js`, сохранён для прослеживаемости. Его93 scoped-пункта не проверяли фиксированную позицию активного описания внутри intro и не являются итоговой приёмкой. После проверки замечания intro разделён на общие CSS grid tracks для заголовков и описаний; финальный прогон выше проверяет оба активных текста непосредственно.

[Предыдущие94 пункта](pre-focus-report.json) на `index-CfmpicL-.js` предшествуют поправке клавиатурной рамки и также не являются финальным результатом. В ранних headless-прогонах копирование синтетического recovery-кода вызывало native `writeText` с выданным clipboard permission; содержимое системного буфера не читалось, возможное влияние на него не подтверждалось. В итоговом прогоне вызов изолирован заглушкой.

Нового выпуска на сервер в этой проверке не выполнялось.

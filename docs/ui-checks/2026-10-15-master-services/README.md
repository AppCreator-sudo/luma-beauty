# U-10-03 — приёмка оставшихся состояний услуг мастера

Проверка **15.10.2026, Asia/Novosibirsk**: **134/134 пункта PASS**, desktop 1440 px и mobile 390/320 px. Необработанных ошибок JavaScript — 0; горизонтальное переполнение — 0; проверенные поля, select, добавление и удаление — от 44 × 44 px. Все 21 снимок просмотрены визуально. Новое изменение приложения для этой карточки не потребовалось.

Проверена действующая форма `ServiceForm` и `ServiceDirectionEditor` в `/v2/studio?tab=services`. Использована новая синтетическая SQLite в `.cache/u10-03-services-*`, сервер `http://localhost:3263` и существующая тестовая подмена поставщика адреса. Настоящие данные и секреты не использовались, внешние браузерные запросы блокировались. Браузер и сервер остановлены; `fixtureStopped: true`, integrity и FK — PASS. Локальный frontend: `index-Bsde624L.js`.

## Что подтверждено

На каждой из трёх ширин:

1. Пустой список и открытая форма сохраняют композицию утверждённого кабинета, цвета, шрифты и круглые аватары; нижней панели нет. Исходные [desktop](../../ui-concepts/2026-10-10-luma/cabinet-review-01/desktop.png), [mobile](../../ui-concepts/2026-10-10-luma/cabinet-review-01/mobile.png), [уточнения компактности](../../V2_CABINET_REFINEMENT.md) открыты для сверки и не изменялись.
2. Браузер блокирует отправку при пустом названии, цене, длительности и направлении; цене −1 и 1000001; длительности 4 и 721; дробных цене/длительности. Во всех десяти вариантах отправлено **0 POST**.
3. Название из пробелов получает настоящий 400 с сообщением «Укажите название услуги», сохраняет поле и не создаёт услугу.
4. Прямой API возвращает 400 для отсутствующих названия/цены/длительности, выхода за числовые пределы, нечисловой цены/длительности и направления вне профиля, с пробелами либо неверным типом. После каждого отказа список услуг идентичен исходному.
5. Цена **0**, длительность **5**, а также цена **1000000**, длительность **720** сохраняются вместе с направлением и читаются после полной перезагрузки. В списке остаётся существующее оформление цены «от».
6. Добавление с ответом 503 или разрывом сети показывает ошибку, сохраняет все четыре поля и данные списка, возвращает доступность кнопки. Следующий настоящий POST 201 создаёт ровно одну услугу; значения цены/длительности/направления сохраняются после reload. Успех показывает сообщение «Услуга добавлена в список.»
7. Два синхронных submit до отрисовки React отправляют **1 POST**. На время удерживаемого запроса форма показывает «Добавляем…», кнопка и поля заблокированы; сохранена одна услуга.
8. Синтетическая старая услуга вставлена только в отдельную тестовую БД без строки направления у мастера с двумя категориями. Она видна в списке с исходными ID, названием, ценой и длительностью; пустой select сопровождается пояснением «Уточните направление для фильтров карты.»
9. Отказ PATCH направления 503 и разрыв сети показывают ошибку, возвращают исходное пустое значение, сохраняют все данные и допускают повтор. Успешный повтор блокирует select и показывает «Сохраняем…», затем убирает пояснение; направление «Брови» остаётся после reload. ID, название, цена и длительность не меняются.
10. Неверное направление PATCH даёт 400 и не меняет сохранённую услугу. PATCH чужой услуги даёт 404; полный кабинет второго мастера остаётся идентичным исходному.

При сетевом отказе существующий общий API показывает браузерный текст `Failed to fetch`. Видимость ошибки, сохранение данных и повтор проверены; локализация общих сетевых сообщений не менялась этой карточкой. Пустое направление API сохранено как действующее правило совместимости старых услуг; новая форма требует явного выбора у многопрофильного мастера.

## Связанные доказательства

Первое добавление услуги/направления/цены/длительности и готовность к публикации уже приняты в [U-10-02](../2026-10-15-master-onboarding/README.md). Удаление, реальные 409, отмена, ошибки, повтор, двойное нажатие, сохранность визитов и чужих данных приняты в [BUG-008](../2026-10-15-master-deletion/README.md). Этот прогон дополняет их оставшимися вариантами U-10-03 и не повторяет весь сценарий удаления.

Машиночитаемый итог: [report.json](report.json). Проверочный скрипт: [verify-master-services.mjs](../../../scripts/verify-master-services.mjs). Новое редактирование названия/цены, новая компоновка, иные роли и маршруты не добавлялись. Этот отчёт фиксирует локальную приёмку; факт серверного выпуска записывается отдельно основным чатом.

## Повторный запуск

После сборки frontend из корня checkout:

```powershell
node scripts/verify-master-services.mjs
```

Каждый запуск создаёт новую изолированную БД и завершает дочерний сервер в `finally`. Для другого свободного локального порта предусмотрена переменная `LUMA_SERVICES_PORT`.

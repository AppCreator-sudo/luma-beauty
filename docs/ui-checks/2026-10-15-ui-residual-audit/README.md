## Новые проверки

- Из `main.tsx` извлечены 17 реально объявленных маршрутов и wildcard; для каждого есть строка матрицы, роль/состояние, эталон/общий слой, реальный компонент и остаток.
- Локальный `matchRoutes` установленного frontend `react-router-dom` принимает `/masters/`, `/me/`, `/studio/`, `/calendar/`, `/salon/`. Точные сравнения Shell эти строки не принимают. Это воспроизведение расхождения маршрутизации; влияние на вид шапки выведено из JSX, нового screenshot нет.
- В `Studio.tsx` прочитаны оба DELETE-handler: отсутствуют catch/busy/сообщение ошибки. В Shell прочитан catch первоначального `/api/me`: отказ превращается в guest. Эти выводы по коду зарегистрированы BUG-008/010; браузерная инъекция отказа остаётся их приёмкой.
- В `Auth.tsx`, `Access.tsx`, `ClientSettings.tsx`, `server.mjs` прослежена доступность восстановления; в `lib/workspaces.mjs` — безусловный 410 приглашений, совместимые staff-ветки и разрешение создания салона любому вошедшему.
- Пересобран индекс 87 карточек, следующий ID U-10-02; проверены статусы, заголовки карточек, существование sources/skills, отсутствие циклов и ссылки документации.
- Все 172 исходных PNG и `reference-manifest.json` под `docs/ui-concepts` сверены по SHA-256 до/после; приложение/frontend/server/lib/tests и сами эталоны не изменены.

Для локальных новых, ещё не добавленных в Git документов проверка использует неизменённую логику `scripts/validate-docs.py` с read-only инвентарём `git ls-files --cached --others --exclude-standard -z` вместо только tracked. Это позволяет проверить новые карточки и отчёт до коммита; исходник валидатора не редактировался. Дополнительно ссылки проверены и внутри новых файлов, которые tracked-only запуск пропускает. Обычный tracked-only запуск предназначен для уже добавленных в Git файлов.

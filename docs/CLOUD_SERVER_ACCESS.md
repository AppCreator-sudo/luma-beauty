## Настройка облачной среды

Среда ещё не создана. Базовые шаги — [CODEX_CLOUD](CODEX_CLOUD.md). Сохранять приватность **Only me**: после расшифровки её подготовленные файлы содержат личные данные.

В Personal vault или Environment variables добавить **LUMA_PRIVATE_BUNDLE_KEY**, значение — из локального import.env после первого знака `=`. Назначить только среде Luma Beauty. Значение процесс читает напрямую; Network secret для этого не подходит. По [OpenAI Docs](https://learn.chatgpt.com/docs/environments/cloud-environments) Network secret подставляется прокси в HTTPS-запросах на 443; это не SSH-туннель. Не отправлять значение в чат или Git.

После установки зависимостей:

```sh
node scripts/cloud-private.mjs verify
node scripts/cloud-private.mjs restore
node scripts/cloud-private.mjs prepare-dev
export NODE_ENV=development
export DATA_DIR="$PWD/.local-data/cloud-dev"
export PORT=3100
export APP_ORIGIN=http://localhost:3100
unset DADATA_API_KEY DADATA_SECRET_KEY
unset YANDEX_CLIENT_ID YANDEX_CLIENT_SECRET VK_CLIENT_ID VK_SERVICE_TOKEN
unset TELEGRAM_CLIENT_ID TELEGRAM_CLIENT_SECRET
export PROMOTIONS_ENABLED=0
npm start
```

APP_ORIGIN заменить на реальный preview URL. Расшифровка и prepare-dev выполняются один раз: существующий результат не перезаписывается. Исходная полная база находится в `.local-data/cloud-source/atelie.sqlite`, доступ/конфигурация — в `.local-data/cloud-access/`. Серверный production.env сохраняется отдельно и **не подключается автоматически** к локальному приложению.

Рабочая `.local-data/cloud-dev` сохраняет бизнес-данные/фото, но очищает действующие сеансы и адреса доставки push. Production VAPID-ключ в неё не копируется; приложение создаёт новый. Это защита от отправки реальных уведомлений во время разработки, а не обезличивание исходного снимка. Полный source остаётся неизменным. Не вводить тестовые данные в live сервер, не коммитить расшифрованные файлы/ключ.

## Предлагаемые постоянные права

Новая SSH-учётная запись **luma-codex**, вход по отдельному ключу. Пароль/действующий локальный вход администратора сохраняются. SSH-ключ запрещает port/agent forwarding и PTY.

В `/etc/sudoers.d/luma-codex` предлагается NOPASSWD только для `/usr/local/sbin/luma-cloud-admin` с аргументами. Помощник root-owned, проверяет команды и пути; оболочка root общего назначения через него не предоставляется. Полномочия:

| Команда | Реальные права |
| --- | --- |
| status / logs | Состояние, health и журнал atelie; журнал может содержать личные данные, не публиковать его целиком |
| backup | Резервная копия всей базы/файлов/конфигурации Luma Beauty на сервере |
| restart | Перезапуск службы atelie |
| install ID | Разбор архива из home/incoming, проверка путей и npm ci от пользователя службы atelie; текущую версию не переключает |
| switch ID | Backup, переключение `/opt/atelie/current`, restart/health; может изменить работающий сайт, запускать только для проверенного согласованного выпуска |
| run COMMAND | Произвольная диагностика от пользователя **atelie**, включая доступ к данным приложения; команды не выполняются от root |

Доступ затрагивает весь Luma Beauty и его личные данные, может менять публикацию и останавливать службу. Текущий запрос не означает разрешение выполнить новый выпуск сейчас. Миграции/несовместимые изменения по-прежнему требуют отдельного плана/разрешения.

Отдельное подтверждение этой учётной записи и точных прав запрашивается вследствие отказа автоматической проверки, а не из-за запрета на передачу данных. До подтверждения не устанавливать помощник и не обходить отказ передачей root-пароля.

## После разрешения установки

Проверить отдельный вход, status, выполнение от atelie и отказ посторонней root-команды/небезопасного ID. Действующая версия/health должны сохраниться. Затем обновить состояние доступа в зашифрованном пакете и повторно проверить import.

Из облачной среды выполнить:

```sh
node scripts/cloud-server.mjs status
```

До успешного прохода этой команды из настоящей среды не объявлять cloud-доступ рабочим. Наличие ключа/разрешённого хоста не доказывает доступность TCP/SSH. Если сеть среды не поддерживает выбранный маршрут, сначала согласовать доступный способ подключения; не добавлять публичный шлюз самостоятельно.

Публикация: сначала build/тесты/совместимость, затем загрузка проверенного архива в `/home/luma-codex/incoming/`, install, проверка/backup, switch и health. Данные не входят в архив release; shared сохраняется. Старую БД не накладывать поверх новых записей. Помощник не делает автоматический откат после изменения схемы.

## Отзыв доступа

Администратор через сохранённый локальный доступ удаляет отдельную строку ключа из `/home/luma-codex/.ssh/authorized_keys` и правило `/etc/sudoers.d/luma-codex`. До удаления проверить точные пути/права, не затрагивать текущий root-вход. Удалить значение из выбранной cloud-среды; для будущего пакета создать новый ключ шифрования. Отзыв не удаляет уже полученные копии, поэтому доступ к prepared files среды тоже нужно пересмотреть.

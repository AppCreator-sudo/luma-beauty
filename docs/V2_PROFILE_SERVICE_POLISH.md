## Направления услуг и совместимость

[Модуль](../lib/service-directions.mjs) создаёт аддитивную связь service_directions(service_id → services.id, category), миграция service-directions-v1. До создания — приватный VACUUM INTO backup. Транзакция, повторяемость, FK/cascade. Старые services и их IDs, работы, визиты и салонные групповые ключи сохранены; старые INSERT из пяти колонок продолжают работать.

Автоматически заполняется только единственное направление мастера. Для неоднозначных услуг нет угадывания по названию; они остаются видимыми в «Все услуги». В кабинетах можно задать/изменить направление уже существующей услуги и выбрать его для новой. Новый dropdown содержит только направления соответствующего мастера. Если выбранное направление позже удалено из профиля, услуга не переносится молча в другое направление; владелец уточняет её.

POST /services и /performers/:id/services поддерживают category; пропущенное поле совместимо со старыми клиентами. PATCH /services/:id/direction и /performers/:id/services/:service/direction разрешены только управляющему соответствующей услугой пользователю; чужие услуги не меняются. Копирование услуг в setup сотрудника сохраняет совместимые направления и прежние связи работ.

## Карта и запись

[Map API](../lib/map-viewport.mjs) возвращает список подходящих услуг, selected_service и актуальное окно. category фильтрует **услуги**, а не только деятельность профиля. service выбирает точную услугу; недействующий или противоречащий фильтру ID даёт 409. soon проверяет полную длительность подходящей услуги; чужая короткая услуга не делает страницу доступной в ближайший час. Для общего hour-фильтра сохраняется один shortest matching scan на исполнителя; детали используют общую подготовку календарей и переиспользуют scan одинаковой длительности.

[Карточка](../frontend/src/components/MapProfileCard.tsx) обновляет время/цену/длительность/исполнителя/ссылку совместно, блокирует запись во время запроса, отменяет устаревший ответ. Изменение услуги сохраняется в истории, Back из записи восстанавливает выбор. Обновление по минуте/focus и истечению окна сохраняет выбранную услугу. Для салона ID соответствует действующему salonServiceKey, выбранный ближайший сотрудник передаётся в запись. Нет времени — честное состояние и переход к расписанию, без старого start.

Leaflet/OSM/SQLite, роли, оплаты и геокодирование не меняются. Никаких тестовых бизнес-данных на рабочем сервере.

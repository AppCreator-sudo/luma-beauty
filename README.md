# Luma Beauty

Бьюти-площадка: равноправные самостоятельные мастера и салоны, работы, карта, гостевая/авторизованная запись и кабинеты клиента/мастера/владельца салона. Ранее называлась Atelie/«Ателье». Разработка только **v2**; утверждённый UI переносится точно, функции и роли сохраняются.

Исходники: закрытый [AppCreator-sudo/luma-beauty](https://github.com/AppCreator-sudo/luma-beauty), ветка main. Настройка облачной среды — [CODEX_CLOUD](docs/CODEX_CLOUD.md); подтверждение GitHub не означает публикацию среды.

## Начало работы агента

Прочитать [AGENTS](AGENTS.md), [инструкцию чата](docs/NEW_CHAT_GUIDE.md), [checkpoint](docs/WORK_CHECKPOINT.md), [текущее состояние](docs/CURRENT_STATE.md). Затем открыть одну карточку из [списка задач](docs/tasks/README.md), её навыки и [точные эталоны UI](docs/V2_UI_REFERENCE_IMPLEMENTATION.md). PNG/старые RELEASE не перезаписывать.

## Запуск из чистого checkout

Node.js **22.22.2** — проверяемая база в `.nvmrc`; минимум backend 22.13 (встроенный node:sqlite). Нужен Python 3 для проверки документации. Два lockfile, два набора зависимостей.

```sh
npm ci
npm --prefix frontend ci
npm --prefix frontend run build
npm run build
python3 scripts/validate-docs.py

```

На Windows использовать `npm.cmd` и `python -X utf8`; на Linux — `npm` и `python3`. Публичный UI **http://localhost:3100/v2/**, API `/api`. Для изолированного запуска установить значения из [cloud-инструкции](docs/CODEX_CLOUD.md): NODE_ENV=development, DATA_DIR=.local-data/cloud, локальный APP_ORIGIN. Затем `npm start`. Пустая база при первом запуске нормальна; производственные данные не импортировать. APP_ORIGIN должен совпадать с браузерным URL (включая cloud preview).

Для Vite hot reload в другом терминале: `npm --prefix frontend run dev -- --host 0.0.0.0`. Его proxy сейчас направлен на backend 3100, UI сохраняет `/v2/`. Готовая сборка обслуживается Express.

## Проверки

- Исходный `npm test` сохранён без изменения. Некоторые тесты используют одинаковые порты: при отдельном поручении на проверку запускать `node --test --test-concurrency=1 tests/*.test.mjs`. Найдены устаревшие тестовые сценарии/зависимость от локального bootstrap; они записаны отдельными задачами, не исправляются в рамках переноса.
- Frontend TypeScript/Vite и существующая корневая сборка выполняются двумя командами выше. Старая оболочка public/app.js сохраняется как совместимость, не эталон UI.
- `python3 scripts/validate-docs.py` проверяет карточки, зависимости, ссылки и отсутствие зависимостей на исключённые из Git файлы. `python docs/tasks/update-index.py` пересобирает список из registry.
- UI проверять в браузере desktop/mobile по макетам; данные — save/reload/права/повтор/конфликт. Нельзя считать правильный внешний вид доказанным по сборке.

## Архитектура и фактические границы

`frontend/src/main.tsx` — React router; `server.mjs`/`lib` — Express, SQLite, загрузки/права. Карта Leaflet/OpenStreetMap, атрибуция обязательна. PostgreSQL/PostGIS/чат ещё не внедрены. При UI не менять провайдера/базу.

Актуальные опубликованные разделы и остатки — в [CURRENT_STATE](docs/CURRENT_STATE.md), с версиями/датами/ограничениями. Кабинет клиента уже работает; его inbox не чат. Вход/регистрация имеют три роли. Яндекс/Telegram/VK ID в текущем экране отключены с «Скоро» независимо от настройки env; реальное подключение отдельно F-02. Пароль остаётся до проверенного перехода.

Гостевая запись: личный ключ в fragment `/v2/visit#…`, сервер хранит hash, API получает ключ в POST. Claim отключает гостевую ссылку. Личный контакт в памяти открытой формы, **полная перезагрузка его сбрасывает**; старое описание двухчасового sessionStorage не относится к текущему v2. Уведомления/inbox реализованы; настоящие OS-жесты и внешняя push-доставка требуют телефона. Лента клиента внутри `/v2/me`, отдельного React-маршрута `/feed` нет.

## Конфигурация и данные

[.env.example](.env.example) — существующий серверный шаблон с production defaults и пустыми полями провайдеров. Не копировать его автоматически в cloud: задать локальные значения из CODEX_CLOUD. Сервер читает process environment; `--env-file` включать только для специально подготовленного локального файла. Production требует HTTPS, рабочие реквизиты остаются на сервере.

В Git **не входят** базы/сеансы/ключи/production uploads/private-client, локальные env/SSH-файл, node_modules, сборка public/v2 и временные каталоги/архивы. Эти локальные файлы не удаляются при подготовке Git. В Git сохраняются исходники, два lockfile, тесты, нужные статические/demo-fixture ассеты, утверждённые PNG/manifest, история выпусков и проектные навыки `.agents/skills`.

Production и cloud development раздельны. Не копировать рабочую базу/ключи в cloud, не запускать старые deploy-скрипты из `deploy` как универсальное обновление: это исторические рецепты с конкретными версиями. Выпуск требует свежей сверки сервера, действующего разрешения, резервной копии и совместимого отката.
